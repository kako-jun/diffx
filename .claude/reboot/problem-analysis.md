# diffx プロジェクト問題分析

## 📅 現状サマリー
- **最終意味のあるコミット**: 2025年8月6日
- **停滞期間**: 約3ヶ月（8月〜11月）
- **現在のバージョン**: 0.6.0
- **最近のコミット**: バージョンバンプとMCP設定のみ

## 🚨 発見された深刻な問題

### 1. CI/CDシステムの崩壊
**問題**:
- `./github-shared/rust-cli-kiln/scripts/testing/quick-check.sh` が存在しない
- `github-shared` シンボリックリンクが作成されていない
- CLAUDE.mdに記載されたプッシュ前必須チェックが実行不可能

**影響**:
- 開発の品質保証が機能していない
- CI/CDパイプラインが壊れている可能性
- 安心してコード変更できない状態

**原因推測**:
- 共有リポジトリ構造 (`/home/d131/repos/2025/.github/`) が複雑すぎる
- シンボリックリンク管理が失敗している
- tasks.mdには完了と書かれているが実際には動いていない

### 2. 過度に理想主義的な計画
**問題**:
- `migration-plan.md`: 740行の超詳細な移植計画
- 14フェーズ、200以上のチェックリスト項目
- lawkit/diffaiへの移植が中途半端な状態

**影響**:
- 完璧主義が開発を麻痺させている
- 本体改善よりも他プロジェクト移植に集中して失敗
- 複雑すぎる品質基準が足かせになっている

**証拠**:
- v0.5.6以降、ほとんど開発が進んでいない
- tasks.mdには多くの「完了済み」項目があるが、実際には機能していない

### 3. マーケティング実行不能
**問題**:
- `.claude/marketing/` フォルダは作成済み
- 戦略・コンテンツ・実行計画が準備済み
- しかし、約3ヶ月間実行されていない

**影響**:
- 技術的には完成しているのにユーザーが増えない
- Reddit投稿は「反応限定的」
- モチベーション低下の原因

**障壁**:
- 技術的問題（CI/CD）が解決できず、マーケティングに踏み出せない
- 不安定なインフラでは自信を持って宣伝できない

### 4. 複雑すぎる2幕リリースシステム
**問題**:
- Release Act1: Rustビルド + GitHub Release + crates.io
- Release Act2: npm + PyPI公開
- workflow_call方式の複雑な共有システム
- 3プロジェクト（diffx/lawkit/diffai）の統一を試みて失敗

**影響**:
- リリースのたびに複雑な手順が必要
- エラー発生時のデバッグが困難
- 小さな変更でもリリースがハードル高い

### 5. 大量の無意味なバージョンバンプ
**問題**:
- 2025年8月6日に0.5.6から0.6.0まで大量のバージョンバンプコミット
- 実質的なコード変更がほとんどない
- 最近のコミット履歴が意味のないノイズで埋まっている

**影響**:
- プロジェクトの健全性を誤解させる
- 実際の進捗が見えにくい
- バージョン番号の信頼性低下

## 📊 根本原因分析

### 主要な失敗パターン
1. **過剰な汎用化**: diffxを成功させる前に、lawkit/diffaiへの移植を考えてしまった
2. **複雑性の暴走**: 共有CI/CDシステムが理解・管理不能なレベルまで複雑化
3. **完璧主義の罠**: 740行の移植計画書など、実行不可能な理想を追求
4. **優先順位の誤り**: マーケティングより技術的完璧さを優先し続けた

### tasks.mdが示す問題
tasks.mdには「✅ 完了済み - diffxでの汎用化」「✅ 完了 - 共有CI/CDシステム実装」と書かれているが:
- quick-check.shは存在しない
- github-sharedリンクは壊れている
- 実際には動作していない

→ **タスク管理と現実の乖離が激しい**

2. 複雑化により管理不能 → CI/CD崩壊
3. 安心して開発できない → マーケティングできない
4. ユーザー獲得できない → やる気低下
5. 3ヶ月放置

- さらなる技術改善に走るが、問題はマーケティング
- 悪循環
