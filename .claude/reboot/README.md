# diffx Reboot Project

## 📌 この reboot フォルダについて

2025年11月14日、diffxプロジェクトは約3ヶ月間の停滞から立ち直るため、徹底的な問題分析と再起動計画を策定しました。

このフォルダには、その分析・計画・実行ガイドが含まれています。

## 📚 ドキュメント構成

### 1. [`problem-analysis.md`](./problem-analysis.md) - 必読
**何が問題だったのか**を徹底的に分析。

主要な問題:
- CI/CDシステムの崩壊（quick-check.sh不在）
- 過度に理想主義的な計画（740行の移植計画書）
- マーケティング実行不能（技術的不安）
- 複雑すぎる2幕リリースシステム
- 大量の無意味なバージョンバンプ

**読むべき人**: プロジェクトの現状を理解したい全員

### 2. [`reboot-plan.md`](./reboot-plan.md) - 必読
**どう立て直すか**の全体計画。

4つのPhase:
- Phase 0: 大掃除（1日）
- Phase 1: CI/CDシンプル化（2-3日）
- Phase 2: マーケティング実行（1-2週間）
- Phase 3: 小さな改善サイクル（継続）
- Phase 4: 成長測定（継続）

目標: **3ヶ月以内に100 GitHub Stars獲得**

**読むべき人**: プロジェクトの方向性を理解したい全員

### 3. [`quick-wins.md`](./quick-wins.md) - 実行ガイド
**今週何をすべきか**の具体的タスク。

Day 1-5の詳細な実行計画:
- Day 1: 大掃除（✓完了）
- Day 2: 不要ファイル整理
- Day 3: CI/CD方針決定
- Day 4: CI/CD実装
- Day 5: 動作確認とコミット

**読むべき人**: 今すぐ作業を始めたい人

### 4. `deprecated/` フォルダ
使わない理想主義的な計画書を格納:
- `migration-plan.md` (740行の理想論)
- `migration-plan-realistic.md` (まだ早い)
- `tasks-old.md` (膨大な旧タスクリスト)

**アクセス**: 必要になったら参照（通常は不要）

## 🎯 リブートの核心

### 3つの気づき

1. **技術は完成している**
   - 6フォーマット対応
   - 3言語エコシステム（Rust/npm/PyPI）
   - ドキュメント完備
   - → これ以上の技術改善は不要

2. **複雑性が開発を麻痺させた**
   - 共有CI/CDシステムが複雑すぎ
   - 3プロジェクト統一は時期尚早
   - 740行の完璧主義的計画
   - → シンプル化が最優先

3. **マーケティングが未実行**
   - 準備は完了している
   - 技術的不安で実行できなかった
   - Reddit投稿は「反応限定的」
   - → マーケティングが真の課題

### リブートの哲学

```
「完璧を目指すな、実行せよ」

- 技術は完成している
- CI/CDはシンプルで良い
- マーケティングが最優先
- 小さく始めて継続する
- ユーザーが全てを教えてくれる
```
