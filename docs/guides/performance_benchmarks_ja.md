# パフォーマンスベンチマーク

このドキュメントでは、`diffx` のコア操作のパフォーマンスベンチマークとパフォーマンス最適化のガイダンスを提供します。

## ベンチマーク結果

### 環境
- **プラットフォーム**: Ubuntu 22.04 (GitHub Actions ランナー)
- **CPU**: AMD EPYC 7763 (または同等のCI環境)
- **Rust**: 1.75+ リリース最適化付き
- **テスト日**: 2025年1月

### コア差分操作

| テストケース | データサイズ | 時間 | スループット |
|-------------|-------------|------|------------|
| 小容量JSON | ~200バイト | **1.3µs** | ~150MB/s |
| 大容量JSON | ~25KB | **281µs** | ~89MB/s |

## パフォーマンス特性

### 時間計算量
- **オブジェクト比較**: O(n) (n = キー数)
- **配列比較**: O(n×m) (n,m = 配列長)
- **ID キー付き配列**: O(n+m) セマンティック追跡付き
- **ネスト構造**: O(深度 × 要素数)

### メモリ使用量
- **小容量ファイル (<1MB)**: ~入力サイズの2倍
- **大容量ファイル (>10MB)**: ~入力サイズの1.5倍
- **ストリーミング**: 未実装（ファイル全体をロード）

## パフォーマンス退行検出

### CI しきい値
- **小容量JSON**: < 2.0µs (50% 安全マージン)
- **大容量JSON**: < 500µs (75% 安全マージン)

### 監視
- **GitHub Actions**: 全PR/プッシュで自動実行
- **週次実行**: 日曜 午前2時 UTC で長期追跡
- **アラート**: しきい値超過時の自動失敗

## 最適化ガイドライン

### 最大パフォーマンスのために

1. **適切な形式を使用**
   ```bash
   # 最高速: バイナリJSONフォーマット
   diffx data1.json data2.json
   
   # 低速: 複雑なネストしたYAML
   diffx complex1.yaml complex2.yaml
   ```

2. **配列比較の最適化**
   ```bash
   # 効率的: IDベース比較を使用
   diffx users1.json users2.json --array-id-key id
   
   # 非効率: 大容量配列でのインデックスベース比較
   diffx large_array1.json large_array2.json
   ```

3. **早期フィルタリング**
   ```bash
   # 関連部分に比較を集中
   diffx config1.json config2.json --path "database"
   diffx data1.json data2.json --ignore-keys-regex "^(timestamp|_.*)"
   ```

### パフォーマンスオプション

```bash
# セマンティック配列比較
diffx file1.json file2.json --array-id-key id

# 内部フィールドをスキップ
diffx file1.json file2.json --ignore-keys-regex "^_.*"

# 効率的な浮動小数点比較
diffx file1.json file2.json --epsilon 0.001
```

## 他ツールとの比較

| ツール | 小容量JSON | 大容量JSON | 機能 |
|--------|------------|------------|------|
| **diffx** | **1.3µs** | **281µs** | セマンティック、マルチフォーマット |
| 従来のdiff | ~2ms | ~50ms | テキストベース、フォーマット敏感 |
| jq + diff | ~5ms | ~100ms | JSONのみ、前処理が必要 |

### 利点
- 構造化データで従来ツールより **10-100倍高速**
- **フォーマット非依存**: JSON/YAML/TOML で同じパフォーマンス
- **セマンティック重視**: 無関係なフォーマット差異を無視

## 実際のパフォーマンス

### 典型的な使用ケース

1. **CI/CD 設定検証** (1-10KBファイル)
   - 時間: < 10µs
   - 適用: リアルタイム検証

2. **API スキーマ比較** (10-100KBファイル)
   - 時間: < 1ms
   - 適用: 開発ワークフロー

3. **大容量データファイル** (1-10MBファイル)
   - 時間: 10-100ms
   - 適用: バッチ処理

4. **ディレクトリ比較** (100+ファイル)
   - 時間: サイズに応じて1-10秒
   - 適用: デプロイメント検証

### パフォーマンスのコツ

1. **バッチ操作**: 複数ファイルにはディレクトリ比較を使用
2. **並列処理**: CI/CDで複数のdiffxインスタンスを実行可能
3. **早期フィルタリング**: `--path` で変更セクションに集中
4. **設定最適化**: データセットに適切な `array_id_key` を設定
